Beyond Social - UI & Design Direction

You are not designing an “AI dashboard.”

You are designing a premium software product that will be used by businesses every day. The UI should feel intentional, elegant, and engineered, not generated.

Overall Design Philosophy

The product should feel like a combination of:

- Linear
- Vercel Dashboard
- Stripe Dashboard
- Notion
- Raycast
- Arc Browser
- Apple Human Interface Guidelines

Every screen should communicate trust, speed, and simplicity.

When users open the application, they should immediately feel that professionals built it.

Avoid trendy design for the sake of looking “modern.”

Design for longevity.

⸻

Absolutely Avoid

Never generate typical AI SaaS designs.

Do not use:

- giant glowing gradients
- neon blue everywhere
- glassmorphism everywhere
- oversized rounded blobs
- floating random cards
- giant hero illustrations
- fake analytics
- fake profile pictures
- random decorative shapes
- unnecessary shadows
- excessive animations
- Dribbble-style concepts that cannot realistically be built

Avoid making every section look like a separate card.

The UI should feel like software, not a landing page.

⸻

Visual Personality

The interface should communicate:

Professional.

Premium.

Minimal.

Fast.

Quiet.

Confident.

Everything should have a reason for existing.

Whitespace is part of the design.

⸻

Layout Principles

Use a strong grid.

Perfect alignment.

Consistent spacing.

Consistent rhythm.

Every screen should feel balanced.

Nothing should appear randomly placed.

Every page should have a clear visual hierarchy.

⸻

Navigation

The navigation should feel closer to Linear than an admin template.

Requirements:

- compact
- collapsible
- keyboard friendly
- clear active states
- beautiful hover states
- smooth transitions

Icons should be minimal.

Typography should do most of the work.

⸻

Cards

Only use cards when they improve readability.

Avoid wrapping everything inside cards.

Sometimes sections should simply exist on the page.

If a card exists:

- subtle border
- very small shadow or none
- generous padding
- consistent radius

Never stack cards inside cards.

⸻

Colors

Neutral-first design.

The interface should primarily use:

- whites
- blacks
- grays

Accent colors should be used intentionally.

One primary accent color is enough.

Status colors:

- success
- warning
- danger
- info

Nothing else.

Color should communicate meaning, not decoration.

⸻

Typography

Typography is the main visual system.

Use a professional font.

Examples:

- Inter
- Geist
- SF Pro (where appropriate)

Clear hierarchy.

Strong contrast.

Readable line heights.

Never oversized headings.

Avoid marketing typography.

⸻

Icons

Use one icon library consistently.

Prefer:

- Lucide

Icons should support text.

Never replace text.

Avoid oversized icons.

⸻

Buttons

Buttons should feel premium.

Primary actions should be obvious.

Secondary actions should remain subtle.

No giant pill buttons.

No oversized gradients.

Hover states should be refined.

Loading states should be elegant.

Disabled states should be obvious.

⸻

Forms

Forms should be clean.

Generous spacing.

Inline validation.

Helpful error messages.

Keyboard accessible.

Visible focus states.

No clutter.

⸻

Tables

Tables should resemble Stripe.

Dense but readable.

Excellent spacing.

Sticky headers where appropriate.

Powerful filtering.

Sorting.

Search.

Bulk actions.

Keyboard navigation.

⸻

Dashboard

The dashboard should answer:

“What matters right now?”

Not:

“How many cards can fit on the page?”

Only surface useful information.

Examples:

Remaining credits

Recent projects

Publishing queue

Generation status

Trend recommendations

Upcoming scheduled posts

Nothing unnecessary.

⸻

AI Chat

The conversational interface should feel closer to ChatGPT or Claude than Discord.

Minimal UI.

Excellent typography.

Streaming responses.

Thoughtful spacing.

Simple message bubbles.

No playful decorations.

⸻

Video Editor

The editor should feel inspired by:

- CapCut Desktop
- DaVinci Resolve
- Final Cut Pro

Requirements:

Timeline.

Inspector.

Preview panel.

Media panel.

Properties.

Everything should feel native.

Avoid browser-looking controls.

⸻

Motion

Motion should be subtle.

Every animation must have purpose.

Use animation to:

- communicate state
- improve understanding
- reduce perceived latency

Never animate for decoration.

Prefer:

- fade
- scale
- slide

Keep animations under 200ms where possible.

⸻

Empty States

Do not use cartoon illustrations.

Use:

- simple icon
- concise message
- one clear action

Example:

“No videos yet.

Create your first AI video.”

⸻

Loading States

Never use generic spinners.

Prefer:

- skeleton loaders
- optimistic updates
- progress indicators

The interface should always feel alive.

⸻

Accessibility

Accessibility is mandatory.

Requirements:

- keyboard navigation
- screen reader support
- semantic HTML
- proper labels
- focus management
- color contrast
- large click targets

No compromises.

⸻

Responsive Design

Desktop is the priority.

Tablet must work.

Mobile should remain usable.

Do not simply stack everything vertically.

Adapt layouts intelligently.

⸻

Code Quality

Every component should be reusable.

Design tokens should power:

- spacing
- colors
- typography
- radius
- shadows

Never hardcode values repeatedly.

Build a real design system.

⸻

Inspiration

Continuously reference the design quality of:

- Linear
- Vercel
- Stripe
- Notion
- Raycast
- Arc Browser
- Apple
- GitHub

Not for copying layouts.

For understanding restraint, spacing, hierarchy, typography, and polish.

⸻

Final Standard

Every screen should pass this test:

“If someone removed the logo, would this still look like software built by a world-class product team?”

If the answer is no, redesign it.

Aim for timeless software design, not trendy AI-generated aesthetics.
