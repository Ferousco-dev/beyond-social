A type superfamily, one designer's coordinated set of serif, sans, slab, and
sometimes mono cuts sharing proportions and construction, removes pairing risk
entirely because the faces were drawn to sit next to each other.

- Examples: IBM Plex (Sans, Serif, Mono, Condensed), Source (Sans, Serif, Code
  Pro), Fira (Sans, Mono).
- Use the serif cut for editorial or long-form content, the sans for UI chrome,
  the mono for code or data, all inheriting the same x-height and stroke
  contrast.
- This is the default choice for a product that needs a code or data surface
  and a marketing surface to feel like one brand, without a design team
  hand-tuning a bespoke pairing.
- Trade-off: superfamilies are more neutral and less distinctive than a
  bespoke pairing, since the whole point is internal consistency over
  personality.

Why: cross-classification pairing risk, mismatched x-height, clashing stroke
contrast, inconsistent numeral styles, is solved at the type-design stage in a
superfamily, so a small team gets a coherent system for free instead of
spending design hours tuning two independently drawn faces to sit together.

Example: "IBM Plex Sans for UI and marketing headlines, IBM Plex Mono for code
snippets and data labels, same x-height and numeral width throughout."

Counter-example: hand-picking a serif from one foundry and a mono from
another because each looked good alone, then discovering their numeral widths
and cap-heights don't line up in a pricing table.
