A first-run empty state is the last screen a new user sees before deciding whether to commit, so it should teach the primary action, not just report that nothing exists yet.

- Replace a bare "No projects yet" with one line explaining what the object is, plus a primary CTA that starts making one.
- Use an illustration or icon only if it clarifies the concept; otherwise it's decoration competing with the instruction.
- Keep the explanatory line to one or two sentences — this is a nudge, not documentation.
- Link the CTA to the exact starting action (open the composer, start the wizard), never to a general help center.
- If the object requires inputs the user doesn't have yet (an image, a script), say so up front rather than letting them discover it mid-flow.

Why: activation is decided in this moment. A brand-new user has no mental model of what a "project" or "render" is in this product yet, so an empty state that only states absence wastes the one screen where the product could instead demonstrate its value proposition and remove the ambiguity about what to do first.

Example: "Your first video hasn't rendered yet. Add a product photo and a script line to generate a 15-second ad." [Create your first video]

Counter-example: "No data." A brand-new user gets zero orientation about what the product does or how to begin, and many will simply leave.
