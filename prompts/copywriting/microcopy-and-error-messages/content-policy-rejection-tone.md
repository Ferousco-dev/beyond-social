A generation blocked by content policy is already a dead end for the user's task, and vague or moralizing copy compounds the frustration by making them feel accused instead of informed.

- Name the specific flagged element when the classifier can localize it — a phrase, an uploaded image region, a named individual.
- Cite the policy category in plain, concrete terms (real person's likeness, copyrighted logo, depicted violence), never just "policy violation."
- Link the edit path back to the exact field or asset that triggered the block, not a general rules page.
- Avoid language that implies intent to cause harm; most blocks are triggered by an incidental detail, not a deliberate attempt to break a rule.
- If the block is a false positive risk (a common name matching a public figure, a generic logo shape), say the trigger plainly so the user can judge whether to edit or appeal.

Why: a policy block already stops the user's work cold, so the copy's only job left is to get them unblocked as fast as possible. Moralizing or vague phrasing adds a second cost — the user now has to guess what they did wrong and whether they're being judged for it — which is what actually drives appeals and support tickets, not the block itself.

Example: "This script mentions a real, identifiable public figure. Remove the name and we'll continue generating."

Counter-example: "Your content violates our community guidelines." This doesn't say which line triggered it or what to change, and its phrasing reads as a verdict on the user's character rather than a note about one detail in a draft.
