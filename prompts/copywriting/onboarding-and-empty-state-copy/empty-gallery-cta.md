The button inside an empty content gallery is often read in isolation, before
the surrounding copy, so its label alone should tell the user what pressing it
produces.

- Put the object of creation in the button label, "New video" or "Generate a
  video," not "Get started" or a bare "+".
- Match the button verb to the actual mechanism: "Generate" for AI-produced
  content, "Upload" for user-supplied files. Conflating them sets the wrong
  expectation for what happens next.
- If multiple creation paths exist, template, blank prompt, upload a
  reference, give each its own labeled entry point rather than one button that
  opens a chooser with no preview of the options.
- Keep any icon literal to the object, a play or video icon rather than a
  generic plus in a circle, so the label and icon reinforce the same idea.
- Size and place the button as the single most prominent element on the empty
  screen. Secondary actions like a help link should be visually quieter.

Why: users scanning an empty screen fixate on the one button before reading
paragraph copy around it. An icon-only "+" or a generic "Get started" forces a
second look at the surrounding text just to learn what clicking does, adding a
step a self-explanatory label removes entirely.

Example: button reads "Generate your first video," a secondary link below
reads "or start from a template."
Counter-example: a bare "+" icon button with no label, relying entirely on
hover-tooltip text that mobile users, who have no hover state, never see.
