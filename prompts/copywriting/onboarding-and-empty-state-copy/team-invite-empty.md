An empty teammates or workspace-members list should explain the specific
workflow collaboration changes, review, approval, shared assets, rather than
present a bare "Invite people" form, because a solo user has no evidence yet
that adding a teammate is worth the friction of typing an email.

- State the concrete workflow unlocked: "Invite a teammate to review drafts
  before they're published," not "Invite your team."
- Show any role distinction the product has, viewer, editor, approver, inline
  in the empty state, not buried in a settings page the user must find
  separately.
- If the plan has a seat limit, state it here rather than letting the user hit
  a paywall mid-invite: "Up to 3 teammates on your plan."
- Offer a low-commitment first step when a full invite feels premature: "Share
  a preview link" as a secondary action next to "Invite a teammate."
- Avoid enterprise-generic language like "Streamline your team's workflow."
  Name the actual object being collaborated on: videos, drafts, campaigns.

Why: most solo users encounter the empty teammates screen without a pending
need, so the copy has to manufacture the use case in one line. Naming the
specific action a teammate would take, approve a draft before it posts, gives
the solo user a concrete scenario to project themselves into, which a generic
invite form does not.

Example: "Invite a teammate to approve videos before they go live, nobody
posts without a second pair of eyes."
Counter-example: an empty state that says only "No team members" above an
email input field, with no indication of what a teammate would be able to do
once added.
