An empty state is not a failure and not a celebration — it's a starting line —
so it needs its own tone register: encouraging without implying the user did
something wrong by not having data yet.

- Lead with what the space will become, not with the absence: "your rendered
  videos will show up here," not "you have no videos yet."
- Give exactly one next action, phrased as an invitation rather than an
  instruction — "generate your first video" reads better than "click here to
  begin," which talks about the UI instead of the outcome.
- Keep energy moderate-warm, below celebration level but above neutral —
  this is anticipation, not achievement.
- Differentiate first-ever-use emptiness (teach, be patient) from
  after-user-deleted-everything emptiness (neutral, no re-teaching, since a
  returning user doesn't need onboarding tone twice).
- Avoid framing emptiness as a problem to fix ("looks a little empty in
  here!") — that projects judgment onto a state the user hasn't acted on yet.

Why: empty states sit at the start of a user's relationship with a feature,
so the tone set there becomes the anchor for every state after it. Treating
the absence of data as neutral or even promising, rather than deficient,
keeps the invitation forward-looking instead of making the user feel behind
before they've started.

Example: "Your generated videos will appear here. Start with a product shot
or a script — either works." — forward-looking, gives two easy entry points.

Counter-example: "Nothing here yet... get started already!" — frames the
emptiness as a shortfall and adds a faintly scolding nudge, which reads as
impatience toward a user who hasn't done anything wrong.
