Most brand voice failures aren't "we weren't funny enough," they're "we were
funny in the wrong place" — so a tone system needs an explicit humor map,
not a general instruction to "have personality."

- Score each context on two axes: stakes (does getting this wrong cost the
  user money, data, or access?) and state (is the user calm or already
  frustrated?). Humor is only safe at low-stakes, calm-state intersections.
- Hard-ban list, regardless of how casual the brand is elsewhere: payment
  failures, account deletion, data loss, security alerts, legal/consent
  copy, accessibility error messages.
- Safe zone: empty states, marketing copy, feature announcements, low-stakes
  confirmations ("logged out"), 404 pages.
- Cap the joke density even in the safe zone — one light line per screen,
  never stacked, so it reads as a brand trait rather than a bit the writer
  is doing.
- Test every joke by reading it back after imagining the worst-case user
  mood for that screen (rushed, on mobile, mid-task) — if it reads as
  flippant in that mood, cut it regardless of how it reads in a relaxed
  read-through.

Why: humor works by lowering the reader's guard, which is exactly the wrong
effect when the reader needs to feel the brand is taking a serious moment
seriously. Mapping stakes and state explicitly turns "is this joke okay"
from a case-by-case judgment call, which drifts inconsistently across
writers, into a checkable rule.

Example: on a 404 page — "This page took a wrong turn. Here's the way back."
— light, appropriate to a genuinely low-stakes miss.

Counter-example: the same light, playful line reused on a "your export
failed and the file may be corrupted" error — identical tone, completely
wrong context, because the stakes axis was ignored.
